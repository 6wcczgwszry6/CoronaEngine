## 实施顺序

1. 修复 01，保证 CPU 场景范围及其 GPU 消费者正确。
2. 修复 02，使 PT/SVGF 可以分别创建并持续渲染。
3. 建立 03 的双 runtime 失败测试，再实施几何发布与消费。
4. 完成 04，取得真实双视图与图像证据，再执行完整验收。若 03 的验证需要图像读回，可先完成 04 的读回部分。

每项独立实现、验证和提交；某一项通过不自动关闭其他项。03 的实际缺陷范围必须由测试确认，04 中相机创建成功与相机实际参与渲染必须分别检查。

## 共同约束

- 保留路径加载时规范化、AABB 复用和 `svgf_magic` 的相机方向修复。
- 静止场景和仅移动相机时，绑定路径解析、物体逐三角形 AABB 重算均为 0 次／帧。
- 不通过调整分辨率、spp、最大深度或关闭降噪取得性能通过。
- 不将共享 GPU 资源或全局活动 pipeline 当作跨 runtime 数据同步的隐含前提。
- 所有失败请求必须明确返回错误；不得提前发布成功版本或无限悬挂截图请求。

## 完整验收出口

| 类别 | 必须保存的证据 |
|---|---|
| CPU 正确性 | 实例、组、场景范围与独立参考计算一致；范围可扩大也可缩小 |
| GPU 正确性 | 光照范围数据与射线命中／确定性小图案读回正确 |
| 模式切换 | PT→SVGF→PT 实际产帧，embedded 来源从内存加载，资源路径正确 |
| 多视图 | 实际 `visible_cameras=2`；不同模式下实际 `active_runtimes=2` |
| 生命周期 | 重载、休眠恢复、隐藏恢复、resize、关闭窗口及 shutdown 无旧资源访问 |
| 性能 | kitchen 预热 20 秒、采样 25 秒，保存条件、样本数、均值、P95 和重算计数 |
| 自动化 | 按 CLion 配置构建；全部已注册测试通过，开启 GPU 冒烟，无内部 SKIP |

构建和测试环境见[执行计划的验证说明](../../superpowers/plans/2026-09-27-kitchen-acceptance-fixes.md)。本轮为文档整理，不更新历史测试数字，也不将未执行的修复测试记为通过。
