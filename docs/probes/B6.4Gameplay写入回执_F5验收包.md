## 2. Engine 接入前置

Engine capability manifest 必须显式广告：

```text
supported_operations:
  gameplay.apply_manifest

supported_gameplay_primitives:
  on_enter
  on_collect
  set_state
  unlock
  complete_objective
```

Engine 必须提供一个由 `EngineWriteGate.invoke_tool()` 调用的 gameplay tool，并返回结构化成功/失败结果及稳定 `receipt_id`。缺任一能力时保持 blocked，不得注册生产写入口。

AI 侧只通过：

```text
make_engine_gameplay_manifest_provider
-> AgentRuntime(gameplay_manifest_provider=provider)
```

注入。禁止 Agent、ProjectGate 或 LANChat 直接持有 C++ tool。

## 3. 固定提交步骤

1. 从同一 Game-ready Snapshot 生成真实 `EntityBindingPlan`。
2. ProjectGate 生成 `GameplayManifest` 与 `ActionProposal`。
3. 记录 `command_id/proposal_id/plan_id/scene_version/payload_hash`。
4. 调用 `AgentRuntime.submit_gameplay_action_proposal()` 一次。
5. 使用完全相同的 `command_id + payload_hash` 再调用一次。

## 4. 必须核对的写链

```text
ActionProposal
-> PlanPatch(patch_type=gameplay_manifest_apply)
-> business_action ToolCallGraph
-> RuntimeGuard authorized
-> gameplay.apply_manifest
-> EngineWriteGate / RuntimeCppBridge
-> Engine receipt
-> custom_gameplay_facts StatePatch
```

逐项断言：

- PlanPatch 含 `payload_schema_version/structured_payload/payload_hash/proposal_id`，`text/items` 不承载 Manifest。
- `payload_hash` 与规范化 GameplayManifest 的 canonical SHA-256 一致。
- 只有五项白名单 primitive；未知 primitive/参数 fail closed。
- RuntimeGuard 记录 `requires_write=true + confirmed=true + authorized`。
- EngineWriteGate 恰好调用一次；不存在 Runtime/Agent 直接 C++ 调用。
- 首次提交产生一个 PlanPatch、一个 `business_action` 图、一个 Engine receipt。
- 重放返回原 patch 身份，零新增图、零新增 receipt、零重复 gameplay component。
- Engine 失败时没有 success fact；错误码稳定且用户可见失败明确。
- Mock、Red/Yellow Gate、stale Snapshot、非 Game-ready entity 均无法构造可提交 Proposal。
