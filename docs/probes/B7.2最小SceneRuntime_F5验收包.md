# B7.2 最小 Scene Runtime F5 验收包

状态：`ready_for_f5`。执行前所有结论均为 `[待F5/实机验证]`。

## 1. 执行人与预计耗时

- 执行人：能够在 VSCode 启动 CoronaEngine F5 的 Engine/AI 集成人员。
- 预计耗时：15-25 分钟；失败后只修当前断点，不扩大到玩法 Demo。
- 前置：B7.1 摘要必须为 `B7_1_CONTROL_READY`，否则不得执行本包。

## 2. 启动前记录

记录以下事实并写入推进记录：

```text
AI HEAD / origin-main
Engine build SHA 或 patch fingerprint
Frontend SHA
本次 room/session ID
日志路径
LANChat history 路径
```

使用全新单人 Session，清空本次测试对应的 RuntimeState、Registry 和聊天历史；不要复用旧 room 或旧 plan。

## 3. 固定场景

只生成：

```text
room_box
room_floor
1 个普通木椅 Actor
```

兼容聊天入口固定输入：

```text
@小女孩 设计一个最小测试房间，只包含房间盒、地板和一把普通木椅
@GM 确认生成
```

第一条 final reply 到达后再发送第二条。不要追加装饰、森林、混合地形、多人或玩法逻辑。

## 4. 自动与人工核对

先运行严格媒体链验收：

```powershell
python docs/probes/r3_f5_log_check.py --profile scene-runtime <本次_corona.log>
```

摘要必须为 `B7_2_SCENE_READY`，并且 WARN/FAIL 均为 0。需要完整 Runtime/R3 摘要时再运行：

```powershell
python docs/probes/r3_f5_log_check.py --json <本次_corona.log>
```

然后逐项核对：

| 域 | 必须成立 |
|---|---|
| 消息 | 两条消息各认领一次、执行一次、final reply 一次 |
| ScenePlan | 只有一个 Runtime plan_id，确认引用稳定 plan/artifact 身份 |
| Batch/ToolGraph | 一个业务 Batch 对应一个 `business_batch` 图，终态一致 |
| Engine | room_box、room_floor、木椅各一个，不反复 reload，不重复 Actor |
| 图片 | 木椅来自真实 `text_to_image`，具有非 Mock `resource_ref + prompt_hash + content_hash + local_path/image_url` |
| 模型 | `generation_mode=image_to_3d`，`source_image_ref/hash` 与图片完全相等，禁止 `text_to_3d` |
| 血缘 | 日志存在木椅的 `R3MediaLineageTrace`，并以 `engine_actor_import` 结束 |
| 身份 | Engine、RuntimeState、Registry、Snapshot、Report 的 entity_id/actor_id/asset_id/version 一致 |
| 几何 | 木椅具有 actual world AABB；`estimated` 不得冒充 actual |
| 渲染 | 木椅具有明确 render observation，不能仅依赖默认 ready |
| 支撑 | room_box/room_floor 使用明确 environment support 语义；木椅为 grounded |
| Snapshot | `plan_id + scene_version` 唯一且 fingerprint 与实体事实一致 |
| Finalizer | Registry -> Consistency Audit -> Snapshot -> Report -> report_ready |
| 终态 | report_ready 后不再无界新增业务图、Actor 或重复终态消息 |
| 查询 | 生成后的状态查询只读，零 PlanPatch、零 Provider、零 Engine 写入 |

## 5. 通过标准

- 三个必要实体全部进入 Engine、RuntimeState、Registry 和 Snapshot。
- 日志证明 `text_to_image -> image content_hash -> image_to_3d -> matching source_image_hash -> Engine Actor import`。
- 任意 `mock_reference`、`text_to_3d`、缺失图片、hash 不符或 Runtime-only Actor 均判失败。
- 三个实体均 Game-ready；若任一项 needs-review，本轮失败并列出具体 `entity_id + readiness_missing_fields`。
- `registry_ready / consistency_audited / snapshot_ready / report_ready` 同版本且顺序正确。
- 无重复 Actor、重复 Batch、重复业务 ToolGraph、重复 final reply。
- Full R3 Gate 继续如实记录，不要求本轮变 Green。
